## Known Issues

- Playthrough re-test pending (fixes committed on main 2026-07-26, bundle rebuilt): (1) "fix: player spawns at the active layer's height" — TS's `levelSceneBuilder.ts:623-624` per-scene-build Y init was unported, so levels whose start layer isn't array index 0 rendered the player a layer low. (2) "fix: culling frustum matches the cropped camera view" — Bevy 0.19's `update_frusta` ignores `sub_camera_view`, so our HUD crop (which *extends* the frame 20% below and 2.5% per side past the base frustum) had everything rendered in those bands frustum-culled: floor tiles vanished at the screen bottom, and culled meshes exposed coplanar geometry behind them. `zones::sync_cropped_frusta` now rebuilds each cropped camera's `Frustum` from `computed.clip_from_view` between `UpdateFrusta` and `CheckVisibility`. (3) "fix: stairs transition to their target stair" — `on_player_moved` passed the stepped-on stair's own id to `begin_stair`, so every staircase faded and respawned the player in front of the stair they'd just entered; it now resolves the stair entity's `target` (`transitionSystem.ts:47`). (4) "fix: holes render open" — the isOpenBottom/isOpenTop per-cell skip (`rendering/dungeon.ts:157-185`) was unported, so floors rendered over every hole and ceilings under every opening; `dungeon.rs::VerticalOpenness` now auto-detects openness from the adjacent layers' grids (same solidity predicate as the fall trigger) with area `openBottom`/`openTop` overrides, applied to dungeon floors/ceilings, wall-entity reveal groups, and pit floors.
- TS's `forceRenderable` mechanism is still unported (pre-existing PARITY-GAPS row): when a pit trap opens above a solid `#` cell, TS force-renders that below-chamber's walls/floor so the player lands in a lit room. Ours leaves the chamber unbuilt — falling through an open pit into solid rock shows black surroundings until this lands. Newly relevant now that holes actually render open.
- macOS launch path: use `scripts/bundle-macos.sh` + `open target/DelveWard.app`. macOS 26 denies activation to bare terminal binaries, so `cargo run` renders but never gets keyboard focus — fine for launch/init smoke tests only.
