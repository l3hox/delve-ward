# Changelog

All notable changes to this project are documented here, following [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added

- Phase 3 dangerous dungeon: signal entities render and wire end to end (levers, pressure plates, tripwires; timed doors with an occupancy-safe blocked-door retry cycle), trap launchers fire rendered projectiles (darts, arrows, fireballs with explosions), status effects tick on player and enemies with screen tints and icons, environment objects (chests, breakable and secret walls, pushable blocks, signs), player vitals (hunger, starvation, torch fuel drain, damage flash), save/load with file-backed slots, autosave, and a death/restart flow, and combat feedback (sword swing, enemy health bars, damage flash and shake, level-up toast). `delve-core` gains dialog and quest runtimes, the player controller, and phase 5 groundwork (spawners, boulders, environment zones) — 595 tests across the workspace. Two adversarial review rounds fixed launcher event delivery, wall-destruction persistence, transition pause semantics, stair-cell double rendering, and UV anchoring.

- Phase 2 loot game: doors with keys and locked variants, stairs with cross-level transitions (fade overlay, level state snapshots restored on return), ground item billboards with walk-over pickups, enemies with billboard sprites, AI, melee combat both ways, XP and loot drops, wall sconces with flickering lights, the pixel-art HUD (health bar, XP bar, mini inventory panel, damage numbers, messages), and the character creation screen. `delve-core` gains the full game state stack (combat, enemy AI, pathfinding, interaction, status effects, loot rolling, signal manager) plus ported `projectileManager` and `saveSystem` modules, all with TS test parity (449 tests). Default dungeon is `ruins.json`, overridable by CLI argument. On macOS, launch via `scripts/bundle-macos.sh` + `open target/DelveWard.app`.

- Phase 1 walkable skeleton in `delve-game`: first-person walking through a loaded dungeon (`dungeon1.json`). Procedural wall/floor/ceiling textures regenerated from the TS canvas algorithms with nearest filtering, per-cell texture resolution, grid-built floors/walls/ceilings, tweened grid movement (step, strafe, 90-degree turns, command queue), and dungeon atmosphere (linear fog, ambient light, flickering player torch). `resolve_textures` joins `delve-core`.

- Phase 0 data foundation in `delve-core`: typed serde model of the dungeon/level schema (levels, layers, grids, charDefs, texture areas, entities, player starts), level and dungeon validation with entity migration ported from the TS `levelLoader` (matching error and warning messages), core primitives (facing, grid walkability, player grid movement, bit-exact `mulberry32`), and data parsing for items, enemies, NPCs, loot tables, quests, and dialogs. The vitest suites for grid and levelLoader are ported as Rust tests, and a gate test validates every shipped file in `assets/levels/` and `assets/data/`.
- Repository seed: Cargo workspace (`delve-core`, `delve-game`), Bevy 0.19 shell opening a native window, asset snapshot from the TypeScript original, planning documents (port plan, decisions, progress), and the autonomous session contract in CLAUDE.md.
